# Design — 002 Store tasks in Postgres so they survive restarts and are shared by every instance

## Decisions

- Storage is Postgres via **psycopg 3** (`psycopg[binary]`) with **psycopg_pool** `ConnectionPool`. Handlers stay sync (`def`), as in 001; FastAPI's thread pool runs them and the pool serialises nothing (the database does). The in-memory `TaskStore` is removed, not kept as a fallback: one code path, and every instance shares state (AC-002.1, AC-002.2). ADR (cross-cutting, outlives the feature): "Postgres via psycopg 3 + psycopg_pool, schema owned by the service and created idempotently at startup, no migration tool yet" — to be created with `cplat adr add postgres-storage-psycopg` (see report).
- Connection settings come only from the environment: the conninfo is `os.environ.get("DATABASE_URL", "")`; an empty conninfo makes libpq use `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` itself. No settings object, no default host. The URL and password are never logged.
- Timeouts (contract "Timeouts"): every pooled connection is opened with `connect_timeout=2`, `options="-c statement_timeout=2000"`, `tcp_user_timeout=2000`, `keepalives=1`; pool checkout `timeout=1.0`. So with the database down `POST`/`GET /tasks` fail in at most ~3 s and answer 503 (AC-002.5).
- Stale connections after an outage: the pool is created with `check=ConnectionPool.check_connection`, so a connection broken during the outage is discarded at checkout and replaced, and the first `GET /tasks` after recovery answers 200, not 503 (AC-002.6).
- Every `psycopg.Error` raised while talking to the database (incl. `psycopg_pool.PoolTimeout`, `OperationalError`, `QueryCanceled`) is turned into one `StorageUnavailable` exception in the store; the app maps it to `503 {"detail": "Task storage unavailable"}` and logs `storage_unavailable` (warning, `error=<exception class name>`). The `POST` runs in one transaction (`with pool.connection() as conn:` commits on clean exit, rolls back on error), so a 503 never leaves a row behind (AC-002.6).
- Schema: created by the service with `CREATE TABLE IF NOT EXISTS` inside a transaction that first takes `pg_advisory_xact_lock(<fixed bigint key>)`, so two instances starting at once do not race on the catalog (spec note: idempotent, concurrent start) (AC-002.7). It runs in the app lifespan at startup; when the database is down at startup the service still starts (not ready) and the store retries `ensure_schema` lazily before the next operation and in `/ready`, so it recovers without a restart. A store flag remembers success so the DDL runs once per process.
- Ordering: `ORDER BY created_at, seq` with `created_at timestamptz DEFAULT now()` (the database clock, the same for every instance) and `seq bigserial` as tie-breaker; never by the uuid (spec note) (AC-002.2, AC-002.3).
- `id` stays `str(uuid.uuid4())` generated by the service, stored in a `uuid` column and returned as its canonical lowercase string (unchanged contract, system A1).
- `/health` stays DB-independent (spec note). `/ready` runs `SELECT 1` through the pool with a 1-second checkout bound (contract).
- Titles containing U+0000 cannot be stored in a Postgres `text` column; `TaskCreate` rejects them with 422 (one extra validation case beyond 001; it never occurs from the web UI). Departs from the contract line "stored and returned exactly as sent" only for that character, which Postgres cannot hold.
- No gitops change from this repo: the spec's "Provided by the system" states the system plan's gitops part wires resource `postgres` (`DATABASE_URL`, `PG*`) into the entry; port and probe paths are unchanged.
- Test database: `testcontainers[postgres]` (dev extra) starts a throwaway Postgres for the test session; `TEST_DATABASE_URL`, when set, is used instead (runners without Docker). No change to the platform-owned `ci.yml` is needed: GitHub-hosted runners have Docker.

Signatures:

```python
# db.py
CONNECT_TIMEOUT_S = 2
STATEMENT_TIMEOUT_MS = 2000
POOL_CHECKOUT_TIMEOUT_S = 1.0
def database_conninfo() -> str: ...                 # os.environ.get("DATABASE_URL", "")
def make_pool(conninfo: str) -> ConnectionPool: ... # open=False, min_size=1, max_size=10,
                                                    # timeout=POOL_CHECKOUT_TIMEOUT_S,
                                                    # check=ConnectionPool.check_connection,
                                                    # kwargs={connect_timeout, options, tcp_user_timeout, keepalives}

# tasks/store.py
@dataclass(frozen=True)
class Task:
    id: str
    title: str
    due_date: date | None

class StorageUnavailable(Exception): ...

class TaskStore:
    def __init__(self, conninfo: str) -> None: ...   # builds the pool, does not connect
    def open(self) -> None: ...                       # idempotent; pool.open(wait=False)
    def close(self) -> None: ...
    def ensure_schema(self) -> None: ...              # advisory lock + CREATE TABLE IF NOT EXISTS; raises StorageUnavailable
    def add(self, title: str, due_date: date | None) -> Task: ...   # one transaction; raises StorageUnavailable
    def list(self) -> list[Task]: ...                 # ORDER BY created_at, seq; raises StorageUnavailable
    def ping(self) -> bool: ...                       # SELECT 1 within 1 s; never raises

def get_task_store() -> TaskStore: ...   # lazily created process singleton from database_conninfo()
def close_task_store() -> None: ...      # closes the singleton if created (lifespan shutdown)
```

Every public store method calls `open()` and, except `ping`/`close`, `ensure_schema()` when the schema flag is not yet set; `ping()` also attempts `ensure_schema()` once the database answers, so `/ready` 200 implies the table exists.

Lifespan (pseudocode):

```python
@asynccontextmanager
async def lifespan(app):
    store = app.dependency_overrides.get(get_task_store, get_task_store)()
    store.open()
    try: store.ensure_schema()
    except StorageUnavailable: log.warning("schema_deferred")
    yield
    close_task_store()     # only the default singleton; test-owned stores are closed by the tests
```

## Contract

Unchanged from 001 for request/response shapes (system A1); additions in **bold**.

`POST /tasks`
- Request `{"title": str, "due_date": "YYYY-MM-DD" | null}`; `due_date` optional; unknown fields ignored.
- `201` `{"id": str, "title": str, "due_date": "YYYY-MM-DD" | null}`, committed: a following `GET /tasks` from any instance holds it as the last element (AC-002.2, AC-002.3).
- `422` FastAPI standard `{"detail": [{"type", "loc", "msg", "input", ...}]}`: title missing, not a string, empty, whitespace-only, over 200 characters after trimming, **or containing U+0000**; `due_date` not a real `YYYY-MM-DD` date; body not an object. Nothing stored (AC-002.4).
- **`503` `{"detail": "Task storage unavailable"}`** when the database is unreachable, the pool checkout exceeds 1 s, or a statement fails/times out; answered within 5 s; nothing stored (AC-002.5, AC-002.6).

`GET /tasks`
- `200` JSON array of task objects, all tasks, oldest first by creation time (`created_at`, then `seq`), no limit; `[]` when none (AC-002.1, AC-002.2, AC-002.7).
- **`503` `{"detail": "Task storage unavailable"}`** as above (AC-002.5).

`GET /ready`
- `200 {"status": "ready"}` when `SELECT 1` succeeds within 1 s (and the schema exists).
- **`503 {"status": "unavailable"}`** otherwise (AC-002.5, AC-002.6).

`GET /health`: `200 {"status": "ok"}` regardless of the database.

Configuration: `DATABASE_URL` (libpq URI) or, when unset, libpq's `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`.

### Test hooks (for the acceptance tests, not public API)

- Database: a session fixture `database_url` in `tests/conftest.py` yields `TEST_DATABASE_URL` if set, else the URL of a `testcontainers.postgres.PostgresContainer("postgres:16-alpine")` (driver-less URI `postgresql://...`). Import `testcontainers` inside the fixture, so tests that do not use it (health, metrics) keep running before the dependency lands. Truncate or drop table `tasks` between tests for isolation.
- A store: `TaskStore(database_url)`; tests own and `close()` it. Inject with `app.dependency_overrides[store.get_task_store] = lambda: s` (used by `/tasks` and `/ready`).
- Restart (AC-002.1): close the first store, build a new `TaskStore(database_url)` on the same database, override again, `GET /tasks`.
- Two instances (AC-002.2): two `TaskStore` objects on the same URL; create through one override, list through each.
- Startup schema (AC-002.7): empty database (table dropped), override, then `with TestClient(app):` runs the lifespan.
- Outage (AC-002.5, AC-002.6): put a test-side TCP proxy between store and database (a small threaded forwarder on a fixed local port); "unreachable" = stop the listener and reset its open connections, "back" = listen again on the same port. A store on an always-closed port (`postgresql://u:p@127.0.0.1:1/x`) is enough for AC-002.5 alone.
- Spec 001's `tests/test_tasks.py` fixture (`store.TaskStore()` without arguments) and its AC-001.7 test (restart empties the list, replaced by AC-002.1) must be updated by the testers: `TaskStore` now needs a conninfo.

## Data

Table `tasks` (created by `ensure_schema`, no migration tool):

```sql
CREATE TABLE IF NOT EXISTS tasks (
    seq        bigserial   PRIMARY KEY,
    id         uuid        NOT NULL UNIQUE,
    title      text        NOT NULL,
    due_date   date        NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

`list()`: `SELECT id, title, due_date FROM tasks ORDER BY created_at, seq`. `add()`: `INSERT INTO tasks (id, title, due_date) VALUES (%s, %s, %s)` with bound parameters only.
